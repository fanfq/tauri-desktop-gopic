# 多文件上传优化

在 Tauri 工程中改造，保留 Tailwind 界面与现有上传协议、配置快照和缓存语义，不自动 commit。

## 并发

每个文件独立 Tokio 异步任务，窗口和托盘共享进程级调度器，最多同时上传 4 个文件；每文件最多 4 个并发分片。批次注册时立即按输入顺序发布全部 queued 任务，执行时转 uploading，只有云端确认并成功提交本地记录后转 done；单文件错误不阻塞其他文件。结果与托盘剪贴板链接维持输入顺序。文件准备、缩略图与缓存提交的阻塞 IO 不占用异步执行线程。

## 分片

保持 >10 MiB 自动分片。S3 分片基准 5 MiB，按现有 10000 片约束增长；七牛保持独立 4 MiB mkblk/mkfile 协议。由分批等待改为滑动并发窗口；完成一片立即补下一片。分片读取使用有长度约束的流式范围读取，避免每文件驻留多份完整分片。进度聚合每个分片已发送字节，最终合并确认前不显示完成。错误后停止启动新片，等待在途请求结束，再执行现有 S3 abort。

## 队列图标

图片在本机生成最多 96px 的 JPEG 缩略图，以 data URL 随事件返回；不放宽 assetProtocol 的任意路径权限，不把原图全量加载进 WebView。缩略图生成限制解码内存及并发，失败回退到类型图标。普通文件按图像、PDF、压缩包、视频、音频、文档、表格、演示、代码、未知文件分类。最窄窗口也保留队列文件图标。

## 验证

本地 HTTP 集成测试证明多文件重叠、并发上限、失败隔离、结果/缓存一致性、分片补位、合并顺序与失败清理。图片缩略图尺寸与回退、文件分类、浏览器队列展示分别验证。执行前端 tests/build/format 与 Rust tests/check。真实云厂商与原生拖放手势仅在实际验证后声明。
