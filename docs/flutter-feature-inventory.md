# GoPic Flutter 功能盘点与 Tauri 预览范围

日期：2026-11-21。依据：flutter_gopic 当前 Dart / Swift 源码、README 和仓库截图；本次未运行 Flutter，也未调用真实云服务。本文为功能盘点和待确认设计建议，不代表迁移已实现。

## 1. 工程现状

- Flutter：4 个主页面，Provider 管理配置与历史，Dart 执行上传、签名、压缩、缓存，Swift 提供 macOS 状态栏拖拽与登录自启动。
- Tauri：React 19 + TypeScript + Vite + Tauri 2，当前为 greet 模板；默认窗口 800×600，尚无 GoPic 业务功能。
- 本次不自动提交，不调用真实上传，不读取用户实际密钥。

## 2. 页面与布局

| 区域 | Flutter 当前布局 | 预览应覆盖 |
| --- | --- | --- |

## 3. 完整功能边界

### 上传

- 文件多选、窗口拖拽、macOS 状态栏拖拽。文件选择入口支持 jpg/jpeg/png/gif/webp/bmp/svg/tif/tiff/ico/avif/heic；各拖拽入口的过滤实现需分别保留和验收。
- 选择当前云配置，校验启用状态、凭证、Bucket、Endpoint；七牛另需公网域名。
- 当前前台批次按文件依次上传，任务显示文件名、进度、速率、错误信息和成功 URL；成功可复制链接。
- 压缩默认关闭，阈值默认 1 MiB、JPEG 质量默认 70；质量限制 1–100。可压缩 jpg/jpeg/png/webp/bmp/tif/tiff；输出 JPEG，只有更小时才采用，否则回退原文件。
- S3 兼容服务采用 SigV4，七牛采用上传 Token。大于 10 MiB 进入分片：S3 Multipart，七牛 mkblk/mkfile，分片并发上限 4。
- 成功后写入历史和本地缓存，更新最近上传项。状态栏批次成功链接自动写入剪贴板；普通上传页提供复制按钮。
- 当前没有用户可操作的暂停、取消、失败重试按钮，不把这些算作已有功能。

### 云配置

- 每个厂商可保存多套配置；可新增、选择、命名、启用、保存和删除。
- 公共字段：配置名称、Access Key、Secret、Bucket、Endpoint/上传域名、公网 URL 前缀、路径前缀。
- 非七牛额外字段：Account/App ID、Region、Path-style URL；Secret 可显示/隐藏。
- 上传与图床共享当前配置；选择器包含已启用且支持上传的配置，并不保证参数已完整，上传时再校验。
- **源码与 README 差异**：README 将 COS/OSS 写为占位，当前 `CloudProvider.supportsS3CompatibleUpload` 对所有非七牛厂商为 true，上传服务走通用 S3 分支，配置帮助也说明使用兼容 Endpoint。应迁移当前代码行为；COS/OSS 实际云端兼容性待真实服务验证，不应宣传为已验证的原生协议支持。

### 图床和本地数据

- 展示本地上传历史，不是远端 Bucket 文件浏览器；按当前配置 ID 和扩展名筛选。
- 本地缓存优先展示，缺失时尝试网络图；加载失败显示占位。
- 单项复制 URL、Markdown、缩略 Markdown，删除本地记录；预览可缩放。
- 多选/全选/取消全选，导出选中的本地缓存到目录，并反馈成功、跳过、失败数量。
- 批量删除与当前配置清空同时删除对应本地记录和缓存，不删云端对象。
- 配置页“清除本地缓存”保留历史；“清除上传历史”清全部历史、保留缓存；这些操作与图床页清空范围不同，不能合并为同一含义。
- 当前所谓“缩略 Markdown”实现为带 title 的普通 Markdown 图片：`![文件名](URL "文件名")`，没有真正生成缩略尺寸 URL。
- 缓存实际通过复制本地源文件保存；迁移时不能仅凭名称将其当作经过缩小的缩略图。

### 配置与桌面集成

- 登录自启动：读取系统状态、更新中禁用、不可用及失败反馈，失败回退原状态。
- 四种命名：保持原文件名、日期/随机短串_文件名、日期/UUID.扩展名、UUID.扩展名。所谓 HASH 为 6 位随机串，并非内容哈希；所谓保持原文件名也会将不匹配字符替换为下划线。
- 保持原文件名为新模型默认；同路径同对象名覆盖云端内容。
- 缓存统计文件数、占用、目录，提供确认弹窗和结果反馈。
- 导出版本化 JSON：version=1、UTC exportedAt、cloud 配置（含明文密钥）。
- 导入校验格式后以新增方式合并，即使 ID 相同也不覆盖本机已有配置；不等同于自动搬迁 Flutter 的历史和缓存。
- 跟随系统浅色/深色主题，版本显示，About 打开项目 GitHub 地址。
- 状态栏只保留最近一次上传入口；点击复制其链接，提供打开主窗口和退出。

## 4. 建议的页面预览设计（待确认）

推荐保留 Flutter 的 macOS 工具型布局并精修，继续采用蓝色主色、轻灰侧栏、细边框、紧凑表单、8px 左右圆角。保留四个主入口及云服务子导航，不添加无关仪表盘。

- 以 1180×800 为主要设计画布，同时检查 1040×720 与窄窗口；正式窗口尺寸需随预览验收决定。
- 上传：保留顶部配置选择与选图，压缩一行展示，拖拽区为主体，任务列表展示混合成功/上传中/失败案例。
- 图床：保留图片优先的网格，批量操作仅在选择后出现；弹窗承载大图与删除确认。
- 云服务：五种厂商共享结构，按厂商显示字段；配置列表与表单双栏并列，避免切换时整页跳动。
- 配置：依次展示自启动、上传命名、缓存、配置导出和导入，危险操作明确范围。
- 预览采用独立示例数据和明确的演示状态入口，覆盖空状态、异常和弹窗。浏览器只演示状态栏外观与状态，不声称已接通原生拖拽。
- 第一阶段仅做全页面可点击预览，不发起云端请求，不接入系统自启动，不写入真实配置或删除真实数据。

可选方向：A 保留布局并精修（推荐，迁移核对成本低）；B 严格复刻原页面（变化最少）；C 重新组织工作台（变化较大，需要重新验收工作流）。

## 5. 后续迁移分工建议

1. 先验收全部页面、弹窗、主题、空状态及任务状态。
2. React 承载页面、交互和展示状态；通过独立服务接口使用预览数据，后续替换为 Tauri 调用。
3. Rust 承载文件读写、配置存储、压缩、签名、网络上传、历史/缓存与原生能力，避免把密钥和签名处理散落到页面组件。
4. 接入多配置与 JSON 导入导出，再做压缩、命名和上传；随后接历史、缓存导出、状态栏和自启动。
5. 分别验证本地行为、真实云端上传、macOS 权限与安装后行为。COS/OSS 的兼容协议需要独立验证。

## 2026-11-21 用户补充范围（覆盖上述图片限定）

- Tauri 上传目标为任意文件，文件选择与拖拽均不得按图片扩展名过滤。
- 压缩仅作用于支持处理的图片；PDF、压缩包、视频、无扩展名文件等保持原样。
- 图床展示所有文件，只有图片具备图片预览；非图片显示类型图标。
- 格式筛选从记录动态生成，支持无扩展名；非图片复制 Markdown 使用普通链接。
- 当前实现仍为交互预览：已接收本地任意文件并模拟任务，未接入云端上传及真实压缩。
